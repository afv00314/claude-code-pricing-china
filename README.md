## 先说结论：Claude Code 不能单独买，Free 版也用不了

Claude Code 是一个跑在终端、IDE 或浏览器里的编码工具，它能调用 Claude 的模型，做代码编写、文件操作、命令执行这类任务。但它的授权方式不是独立售卖的订阅，而是绑定在 Claude 的会员等级上。

这意味着两件事：

第一，Claude 的免费版不包含 Claude Code，免费账号在终端里登录会被挡住。
第二，你不需要、也没办法"给 Claude Code 单独开一个号"。所有可选项都在 Claude 的订阅体系里。

顺带说一句团队场景。Team 和 Enterprise 的座位类型会直接影响 Claude Code 能不能用、以及是不是要走按量计费，规则比个人档位细得多，而且官方在不同渠道的解释并不完全一致。如果你是以个人身份买，这一块可以直接跳过。

Claude 官方订阅接受的是海外支付方式。国内用户在这一步遇到的典型情况是：

- 手里的 Visa / Mastercard 是国内银行发的，页面直接提示支付失败，而失败原因往往不是余额，是发卡地区、账单地址和风控综合判断的结果。

## 代付和代充是两回事，别混着理解

平台侧的办理方式其实有两种，适用人群完全不同。

**代付（自购）模式**：你已经有 Claude 账号，账号归你。插件获取 Session 后由平台代付，网络环境需要自己准备好。适合已经有账号、想把订阅续在自己名下的人。

**代充模式**：你没有账号，或者不想自己注册。向平台提供一个没有注册过该服务的新邮箱，由平台完成注册和开通，再把账号信息交给你。这条路径省事，但账号是平台注册的，长期归属和安全性需要你自己权衡。

如果你的目标是"用 Claude Code 写代码"，重点应该放在前者。代充出来的新账号绑定关系不在你手上，后续续费、找回、申诉都会更麻烦。

## 订阅开通之后，这几个坑会立刻咬人

订阅成功了不等于 Claude Code 就能按预期跑。三个最常见的问题：

**环境变量的坑。** 如果你的系统里设置了 `ANTHROPIC_API_KEY`，Claude Code 会优先用这个 key 认证，所有请求按 API 价格计费，而不是消耗你的订阅额度。很多人是在收到账单之后才发现这件事。用 `/status` 命令可以确认当前计费来源。

**登录方式选错。** 首次登录时会让你选认证方式，要选的是带订阅的 Claude 账号，不是 Console 账号。如果不小心用了 Console，执行 `/logout` 退出，再 `claude update`，然后重启终端重新登录。

**额度是共享的。** IDE 里的 Claude Code、终端的 Claude Code、网页版的 Claude 用的是同一份额度。想拿订阅去跑 CI、定时脚本或者无人值守的 agent，会直接把白天交互用的量吃掉。这类自动化任务更适合单独走 Console 的 API key。

## 常见问题

**Claude Code 有免费版吗？**
没有。免费账号无法使用 Claude Code。

**能单独买 Claude Code 的会员吗？**
不能。它没有独立订阅，只能通过 Claude 的 Pro 或 Max 订阅获得授权。

**买了 Pro 之后，终端里要怎么认证？**
用你购买订阅的同一个 Claude 账号登录即可，不需要额外配置。网页版、桌面端、移动端共享同一份额度。

不是。它是第三方订阅辅助平台，账号归你、付款由它代办。这一点在决定之前要清楚。

**价格会变吗？**
会。平台价格随汇率和运营成本浮动，官方也调整过额度规则。下单前看站内实时价格，不要依赖旧文章里的数字。
